# 제출 전 마무리

이 세션에 하네스 작업 규칙(`작업 규칙 (Codex)`)이 적용돼 있지 않으면 먼저 `hx-analyze` 스킬 폴더의 `RULES.md`를 읽고 따른다(과제 안내·기존 지침 우선).

**제출물 확정 전에만 쓴다.** 이미 확정했거나 후속 서술형 단계라는 맥락이면 아무 도움도 하지 않고, AI 없이 직접 답해야 한다고만 짧게 알린다. 단계가 불분명하고 실제 평가 문항처럼 보이는 요청이면 먼저 단계만 확인한다.

## 1. 제출 준비 점검 (각 항목을 실제로 확인)
- 과제 안내의 필수 파일명·경로·형식과 요구사항 문서의 모든 Must를 대조한다. 누락은 무엇을 고칠지 먼저 알리고, 시간이 없으면 한계로 남긴다.
- README의 실행 방법으로 핵심 경로를 한 번 실행한다. 이미 유효한 검증은 PLAN.md를 참조하고 전체를 다시 돌리지 않는다.
- 원래 README 아래에 `문제 정의 / 실행 방법 / 구현한 기능 / 검증 결과 / 한계`가 있는지 확인하고, 없으면 실제 기록만으로 짧게 덧붙인다.
- 문서에 `결정 대기`, `TODO`, 같은 역할의 결과물이 두 개 남아 있으면 확정 전에 정하라고 알린다.
- 비밀정보 후보는 파일명만 찾는다. 예: `rg -l --hidden -i 'api[_-]?key|secret|token|password' -g '!.git/**' -g '!.agents/**' -g '!node_modules/**' .` 값은 출력하지 않는다. 결과 없음과 명령 실패를 구분한다.
- 디버그 파일·임시 산출물·.env가 제출에 섞이지 않았는지 보고, 본인이 띄운 검증 프로세스만 정리한다. 화면 확인용 서버는 유지한다.
- Git 훅이 금지된 자동화·외부 전송을 하지 않는지 먼저 확인한다. `git diff`로 변경을 검토하고 과제에 필요한 경로만 스테이징한다(`git add .` 금지). 설치용 `.agents/`·비밀정보·임시 파일을 무심코 포함하지 않는다. 마지막 로컬 커밋 명령을 실행하거나 보여 주고 `git status`를 확인한다. push하지 않는다. 시간이 없으면 커밋보다 저장과 제출이 먼저다.

판정: **제출 준비됨 / 수정 필요 / 확인 불가** 중 하나와 이유.

## 2. 담당자 공유 메시지 초안 (5줄 이내)
만든 것, 받는 방법(파일·경로), 쓰는 방법, 담당자가 알아야 할 한계, 다음 단계. 전송은 사용자가 한다.

## 3. 설명 준비 확인 (확정 전)
- `$hx-explain`의 구현 지도·결정 카드가 최신 코드와 맞는지 확인한다. 아직 안 했고 시간이 있으면 지금 `$hx-explain`을 권한다. 시간이 없으면 핵심 기능 하나의 `입력 → 처리 → 출력`을 파일·함수 이름으로 5줄 안에 정리한다.
- DECISIONS.md에 없는데 코드에 숨은 핵심 선택(기준, 가중치, 동점 처리, 기본값, 근사, 라이브러리)이 있으면 알리고, 사용자가 확인하면 기록한다.
- `사람 개입` 표에 `이유 확인 필요`가 남아 있으면 확정 전에 사용자에게 묻는다.
- 모범 답안은 만들지 않는다.

## 4. 제출 순서 안내 (사용자가 직접)
1. 에디터 저장 상태("저장됨")와 필수 파일 경로를 확인한다.
2. "제출하고 문제풀기"로 미리보기를 연다. 미리보기는 전체 파일 목록이 아닐 수 있다.
3. 확정은 되돌릴 수 없다. 확정 후에는 파일 수정과 AI 도움이 끝난다.

보고 형식: `제출 준비 상태 / 남은 필수 조치 / 미검증·한계 / 공유 메시지 초안`.
