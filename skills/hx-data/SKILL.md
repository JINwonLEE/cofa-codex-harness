# 데이터 과제: 계산 전에 기준부터

실제 README·데이터 사전·제공 파일에서 출발한다. 반도체 회사의 대회라는 이유로 수율 예측·대시보드·모델이 과제라고 짐작하지 않는다. 과제가 요구하지 않으면 모델·웹앱을 덧붙이지 않는다.

**원본 데이터는 수정하지 않는다.** 정제·변환은 별도 파일이나 코드로 만들고, 각 점검은 명령 한 번으로 다시 실행할 수 있게 스크립트로 남긴다. 결과는 숫자로 적는다. 데이터 파일을 통째로 출력하지 말고 앞부분·요약만 본다.

## 1. 데이터 계약 (먼저 문장으로 확정)
- **한 행의 의미**: 개체 하나인지, 검사 시도 한 번인지, 결함 한 건인지, 센서 관측 한 번인지
- **식별 키**: 무엇이 한 개체를 유일하게 정하는가 (예: lot+wafer, ID가 상위 단위마다 재사용되는지)
- **시간·단위**: 시간대, 기간, 단위(개수·비율·mm 등), 앞자리 0이 있는 ID는 문자열로 보존
- **분자·분모**: 지표를 문장으로 먼저 쓴다. 예: "이 단계·기간에 최종 판정이 있는 서로 다른 대상 중 통과한 비율"
- **결측·재검사·제외 정책**

명시된 값과 가정을 나눈다. 결과를 바꾸는 미확정 조건만 담당자 질문으로 만든다(`$hx-interview`). 답을 기다리는 동안 스키마·키 중복 점검은 진행한다. 중요한 분모나 정책을 추측해 최종 수치를 확정하지 않는다.

## 2. 점검 목록
1. **모양**: 행·열 수, 자료형, 주요 열 분포, 타깃이 있으면 비율
2. **키와 중복**: 완전 중복 행, 키 중복, 같은 키인데 값이 충돌하는 행
3. **결측**: 열별 결측률. 결측 자체가 의미(측정 생략 등)인지 확인. 이유 없이 0이나 평균으로 채우지 않는다
4. **범위 이상**: 음수 수량, 비정수 개수, `통과 > 검사`, 분모 0, 단위 혼재
5. **시간**: 정렬 여부, 시간대(UTC/KST) 혼재, 날짜 경계(포함·미포함), 기간별 분포 변화
6. **판정 경계**: 기준값과 같을 때 통과인지 실패인지(`>=` vs `>`)를 근거와 함께 확정

## 3. 계산에서 지킬 구분
- `결함 건수`는 `불량 개체 수`가 아닐 수 있다. 한 개체에 결함이 여러 개일 수 있으니 `1 - 결함/검사`를 수율로 쓰지 않는다.
- 합산 비율 `sum(통과)/sum(검사)`와 행별 비율의 평균은 다른 통계다. 요구받은 것을 쓰고 이름을 정확히 붙인다.
- 최초 검사 통과율, 최종 판정 통과율, 전체 시도 통과율을 구분한다. 재검사를 무조건 지우거나 모두 더하지 않는다.
- **결합(join) 전후로 행 수·고유 개체 수·분자·분모 합계를 대조한다.** 다대다 결합으로 늘어난 행을 실제 수량처럼 보고하지 않는다. 필요하면 먼저 원하는 단위로 집계한 뒤 결합한다.
- 관리한계 이탈은 조사할 신호이지 불량 확정·원인 확정이 아니다. 실제 규격 없이 임의 합격선이나 Cpk를 만들지 않는다.
- 분모가 없거나 0이면 `산출 불가`로 표시하고 0%와 구분한다.

## 4. 모델·예측이 있다면
- **누수**: 판정 이후에만 알 수 있는 열, 타깃과 거의 1:1인 열, 이름에 결과·판정·label·flag가 들어간 열을 의심한다. 단일 열로 성능이 비정상적으로 높으면 누수 후보다.
- **분할은 실제 사용과 같게**: 시간 순서가 있으면 과거로 학습하고 미래로 평가한다. 같은 lot·wafer가 학습과 평가에 걸치지 않게 한다. 전처리는 학습 구간에서만 맞춘다.
- **기준선 먼저**: 다수 클래스·단순 규칙 같은 가장 단순한 방법의 숫자를 먼저 얻고, 개선은 기준선 대비로 말한다.
- **지표는 운영 조건에서**: 담당자가 준 제약(오탐 허용치, 처리량 등)을 지표에 넣는다. 임계값은 검증 구간에서 정한다. 불균형이면 정확도를 주 지표로 쓰지 않는다.
- **숫자 설명**: 무엇을 측정했는지, 왜 더 좋지 않은지, 기준선과의 차이가 잡음보다 큰지 답할 수 있어야 보고한다. 너무 좋으면 누수부터 의심한다.

## 5. 검증과 기록
- 작은 확정 사례를 손계산하고 코드 결과와 대조한다(정상 + `분모 0`, 결측, 중복 키, 경계값).
- 결과에는 모집단·기간·단위·제외한 행 수와 이유·남은 한계를 붙인다. 코드 실행 성공과 통계 가정 확인은 따로 보고한다.
- 데이터 처리 결정(제외·대체·정책 선택)은 DECISIONS.md에, 점검 수치와 손계산 대조는 PLAN.md 검증 결과에 남긴다.

데이터는 응시 환경 밖으로 보내지 않는다. 공개 기술 검색에 데이터나 과제 내용을 넣지 않는다. 후속 서술형 단계에서는 이 스킬을 쓰지 않는다.
