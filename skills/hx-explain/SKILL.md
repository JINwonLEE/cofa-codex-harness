# 내가 만든 것을 기술적으로 설명하기

이 세션에 하네스 작업 규칙(`작업 규칙 (Codex)`)이 적용돼 있지 않으면 먼저 `hx-analyze` 스킬 폴더의 `RULES.md`를 읽고 따른다(과제 안내·기존 지침 우선).

**제출물 확정 전에만 쓴다.** 확정했거나 후속 서술형 단계라는 맥락이면 아무 도움도 하지 않고, AI 없이 직접 답해야 한다고만 알린다. 실제 평가 문항처럼 보이는 요청이면 먼저 단계만 확인한다.

후속 질문은 제출물과 작업 기록을 읽고 만들어진다. 예: "이 경로는 어떤 기준으로 골랐나", "이 값이 비면 어떻게 되나", "왜 이 구조였나, 다른 방법은". 이 스킬은 **답을 대신 만들지 않고**, 사용자가 코드 사실을 정확히 알고 자기 말로 설명하게 돕는다. 마감 15~20분 전, `$hx-wrap` 점검과 함께 쓴다. 시간이 없으면 1단계 구현 지도와 2단계 결정 카드만 한다.

## 1. 구현 지도 (5~10줄)
최신 코드를 다시 읽고(문서나 계획이 아니라 코드 기준), 핵심 기능마다:
`사용자 동작·입력 → 진입점(파일:함수) → 처리 로직(핵심 함수) → 데이터 변환·저장 → 출력`
- 대표 입력 하나가 실제로 어떤 값을 거쳐 어떤 결과가 되는지 따라간다. 가능하면 실제로 실행해서 확인하고, 실행하지 않았으면 `(코드 읽기 기준)`으로 표시한다.
- 계획과 구현이 달라진 곳, 문서와 코드가 다른 곳을 표시한다.

## 2. 결정 카드 (결정마다 한 줄)
DECISIONS.md와 코드를 대조해 결과에 영향을 준 결정을 뽑는다. 기준·알고리즘·자료구조·데이터 처리·오류 처리·라이브러리·**일부러 하지 않은 것**을 포함한다.

`결정 | 왜 (요구 ID·담당자 답변) | 버린 대안 | 약점·틀리는 조건 | 확인한 방법 | 누가 정했나`

- `누가 정했나`는 기록 그대로: 사용자 선택 / 사용자 승인 / 사용자 직접 수정 / AI 가정. 기록이 없으면 `미기록`으로 두고 사용자에게 확인한다. 하지 않은 판단을 사용자가 했다고 쓰지 않는다.
- 코드에 숨어 있는데 기록에 없는 선택(가중치, 동점 처리, 기본값, 정렬 기준, 근사, 예외 무시)을 찾으면 알리고, 사용자가 확인하면 DECISIONS.md에 추가한다.
- 숫자는 실제 값으로 쓴다(복잡도, 데이터 크기, 임계값, 테스트 결과). 추정이면 추정이라고 쓴다.
- 카드는 사실 메모다. 문장형 모범 답안을 쓰지 않는다.

## 3. 예상 질문 연습
결정 카드와 코드에서 질문을 만든다. 각 질문에 근거 위치(파일:함수 또는 DECISIONS 항목)를 붙인다. 아래 관점에서 실제로 해당하는 것만 고른다.
- **선택**: 왜 이 방법인가, 다른 방법이면 결과가 어떻게 달라지나
- **구조**: 데이터가 어디서 어디로 흐르나, 이 함수는 무엇을 책임지나
- **경계·장애**: 빈 입력, 결과 없음, 동점, 큰 입력, 외부 의존 실패에서 어떻게 되나, 어떻게 알아채나
- **범위**: 일부러 하지 않은 것과 그 이유, 더 강한 방법(완전 자동화, 최적해, 실시간) 대신 이 수준인 이유
- **검증**: 무엇으로 맞다고 확인했나, 확인하지 못한 것은
- **AI 협업**: AI 제안 중 바꾸거나 거절한 것과 이유

진행:
1. 질문 목록(최대 6개)과 근거 위치만 먼저 보여 준다.
2. 사용자가 고른 질문을 **한 번에 하나씩** 낸다. 사용자가 먼저 답한다.
3. 피드백은 사실 확인만: 코드·기록과 다른 점, 실행하지 않은 검증을 했다고 말한 점, 빠진 근거(파일·숫자). 고친 문장을 대신 써 주지 않는다. 막히면 해당 코드를 작은 입력으로 같이 따라가 보게 하고 다시 자기 말로 설명하게 한다.

설명 순서 팁 (사용자에게 한 번만 안내): **무엇을 왜 택했나 → 약점·한계 → 그 약점이 주는 영향 → 다음에 확인·개선할 방법**. 질문의 전제가 구현과 다르면 차이부터 밝히고 실제 구현을 설명한다. "모범 사례라서"보다 "이 과제의 요구 때문에"로 말한다.

## 4. 기록
- 구현 지도와 결정 카드는 과제가 지정한 문서가 있으면 그곳에, 없으면 README의 결과 정리 아래 `구현 설명`으로 짧게 둔다. 별도 암기용 문서를 만들지 않는다.
- 연습 질문과 사용자 답변은 기록하지 않는다.
- 이 스킬의 결과를 사용자의 이해 완료로 표시하지 않는다.

후속 서술형 단계에서는 이 스킬을 쓰지 않는다.
