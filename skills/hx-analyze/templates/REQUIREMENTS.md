# 요구사항

과제가 같은 역할의 문서를 지정했다면 그 문서를 쓴다. 구현 상태·검증 결과는 PLAN.md에 둔다.

## 문제 정의
- 누가 / 어떤 상황에서 / 무엇을 판단하거나 하려고 쓰는가:
- 지금 불편한 점:
- 성공하면 달라지는 것:
- 입력 (형식·규모·출처) / 출력 (형식·사용처):
- 실행 환경·제약:

## 요구사항
| ID | 구분 | 요구·기대 동작 | 출처 | 확인 방법 |
|---|---|---|---|---|

구분: Must / Should. 출처: 문서 경로:줄, 담당자 답변 번호, 또는 (가정). 필수 제출 파일도 요구사항으로 적는다.

## 기준 사례
- 대표 입력 → 기대 출력 (근거):
- 중요한 예외 입력 → 기대 동작:

## 담당자 질문과 답변
| 번호 | 질문 | 답변 요약 | 영향받는 요구 ID |
|---|---|---|---|

## 가정과 미해결
| 항목 | 가정 또는 질문 | 틀리면 영향 | 해소 근거 |
|---|---|---|---|
